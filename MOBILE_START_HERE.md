# Учебная арена Mobile 1.2

18 предметов, 17 игр, аккаунты с обязательными фамилией и именем, класс 1–11, рейтинг месяца и архив победителей. Контрольная GitHub 3.0 сохранена отдельно.

## Проверка присланного адреса

Новый адрес проверен: сервер возвращает HTTP 200, API `version: 2`, `ready: true`, общий рейтинг читается. База уже настроена. Сообщение со скриншота не означает, что этот адрес не работает: опубликованный сайт мог обращаться к старой ссылке из переменной GitHub ARENA_API_URL или использовать закэшированный JS.

В этой сборке указан новый адрес:

https://script.google.com/macros/s/AKfycbxjK4M8ckSNrhryCgUeQVtbDd6-DfuaAOwqT65yQ0H8jCKfJMEMCW3I9vy_qgjQ2pvkMw/exec

Для **новых** функций фамилии/имени и месячного конкурса требуется сервер Mobile 1.2, API 3. Существующий работающий сервер API 2 нужно обновить указанным ниже порядком, сохранив тот же URL и ту же базу.

## Обновление сервера — сделайте сначала

1. Откройте **тот же проект Apps Script, которому принадлежит последний URL**. Если уже есть аккаунты, не создавайте другой проект и не удаляйте старую таблицу.
2. Полностью замените `Code.gs` содержимым файла `backend/google-apps-script/Code.gs` из этого архива. Код также выдан отдельно файлом `Arena_Mobile_1_2_Code.txt`.
3. В настройках редактора включите показ **appsscript.json**. Замените его содержимое файлом `backend/google-apps-script/appsscript.json` из архива. Для таймера добавлено разрешение `https://www.googleapis.com/auth/script.scriptapp`. Если оставить старый manifest только с правом на таблицы, создание автоматического таймера может завершиться ошибкой разрешений.
4. В редакторе выберите функцию **setup → Выполнить**. Предоставьте запрошенный доступ к Google Таблицам и создание автоматического таймера. **Не запускайте doPost вручную.**
5. Setup использует прежнюю базу, если её адрес уже сохранён. Иначе подключит таблицу, из которой открыт скрипт. Если проект самостоятельный и таблицы нет, setup создаст её автоматически. Ссылка на базу появится в журнале выполнения: «База настроена: …».
6. Для старой базы будут добавлены столбцы фамилии и имени и лист MonthlyWinners; при необходимости — столбцы класса и коэффициентов. Существующие аккаунты, проверочные значения паролей и накопленные баллы сохраняются. Секрет `AUTH_PEPPER` не меняется. Если в непустой базе он утрачен, setup остановится и попросит восстановить прежний секрет — так пароли не будут испорчены молча.
7. Откройте **Развернуть → Управление развертываниями → карандаш → Версия: Новая версия → Развернуть**. Используйте существующее веб-развертывание, чтобы сохранить URL. Запуск — от вашего имени, доступ — «Все».
8. Откройте `/exec` в браузере. В ответе обновлённого кода должны быть `version: 3` и `ready: true`. Если `version` меньше 3, опубликован прежний код без новых функций. Если `ready: false`, setup не завершён в этом проекте.

В новом окне входа есть кнопка **«Проверить подключение»**. Она различает старый серверный код и неготовую базу. Регистрацию следует проверять после готовности сервера.

Не публикуйте саму таблицу и Script Properties. В GitHub находится только публичный адрес `/exec`, а не секреты и не пароли.

## Аккаунт и класс

- Пароль — от **6 до 128 символов**. Старые более длинные пароли продолжают работать.
- На регистрации обязательно выбрать свой класс **1–11**. Без класса сервер аккаунт не создаёт.
- Старые аккаунты без класса после входа один раз выбирают класс. Прежние баллы не пересчитываются и не удаляются.
- Класс закрепляется за аккаунтом. Для исправления или перехода в следующий класс учитель изменяет значение в столбце `grade` листа `Users` на целое число 1–11. Сам ученик не может свободно переключать класс ради награды.
- Класс виден в профиле. До запуска темы показано, сколько баллов даст её решение.
- Фамилия и имя вводятся в отдельные обязательные поля (2–40 букв каждое). В рейтинге показывается «Фамилия Имя», а не псевдоним. Эти сведения будут публичны в таблице результатов; форма регистрации сообщает об этом.
- Старым аккаунтам предлагается один раз заполнить фамилию и имя. Баллы сохраняются. Пока профиль не заполнен, он не участвует в публичном рейтинге и конкурсе, а новые рейтинговые сессии не открываются.

Пароли не хранятся открытым текстом: клиент использует PBKDF2-HMAC-SHA256, 600 000 итераций и индивидуальную соль; сервер хранит HMAC-проверочное значение с секретом из Script Properties. Значение длины пароля передаётся отдельно для проверки протокола; сам пароль серверу не отправляется.

## Начисление баллов

Полная награда — 10 баллов за верное полное задание. Сравнивается класс аккаунта с классом выбранных заданий; разница считается одинаково в обе стороны.

| Разница классов | Доля | Баллы |
| --- | ---: | ---: |
| Свой класс | 100% | 10 |
| 1 класс | 50% | 5 |
| 2 класса | 40% | 4 |
| 3 класса | 30% | 3 |
| 4 класса | 20% | 2 |
| 5 и более | 10% | 1 |

Пример: ученик 6 класса получает за 6 класс +10, за 5 или 7 — +5, за 4 или 8 — +4, за 1 или 11 — +1.

Эти правила одинаковы во всех 17 играх. Энергия, урон, этажи, доставка, победа и другие игровые счётчики в рейтинг не переводятся. В строительстве считается полное задание, а не каждый фрагмент. Ошибка даёт 0. В локальной дуэли аккаунт получает баллы за игрока 1; второй играет гостем. Для двух отдельных аккаунтов используйте два устройства в соло.

Награда закрепляется сервером за игровой сессией и не берётся из запроса клиента. Между зачтёнными верными ответами одного аккаунта — не менее 5 секунд во всех играх и на всех устройствах. Быстрые ответы действуют в самой игре. Повторная отправка события не начисляет баллы второй раз. Профиль и класс фиксируются в момент открытия рейтинговой сессии, чтобы отложенные результаты не меняли стоимость задним числом.

Сессия длится до 45 минут; после этого заново выберите тему. Уже открытая сессия может дослать результаты после восстановления сети в течение семи дней. Очередь — до 500 событий на аккаунт; для разных аккаунтов очереди отдельные. Гостевые результаты задним числом в аккаунт не переносятся.

Это учебный рейтинг с базовыми ограничениями, не защищённая система призовых соревнований: правильность ответа по-прежнему определяет игра на устройстве. Для строгого соревнования нужна серверная выдача задач и проверка самих ответов.

## Месячный конкурс

- Вкладка **«За месяц»** показывает текущий календарный месяц. **«За всё время»** сохраняет накопленные очки. **«Победители»** показывает результаты завершённых месяцев.
- Месяц определяется по часовому поясу `Asia/Qyzylorda` (Казахстан). Баллы относятся к месяцу, когда сервер принял результат. Если решение выполнено офлайн в конце месяца, а отправлено в следующем, баллы попадут в следующий месяц.
- Первого числа таймер Apps Script запускает функцию `closeMonthlyLeaderboard` примерно около 01:05. Это не рассылка: функция только сохраняет победителя в Google Таблицу. Точное время запуска Google может сдвинуть в пределах планировщика.
- Побеждает игрок с максимальной суммой за месяц. При равенстве выше тот, кто раньше достиг итоговой суммы. При полностью совпавшем времени применяется стабильный порядок идентификаторов.
- Победитель сохраняется в новом листе `MonthlyWinners`: месяц, фамилия, имя, класс, баллы и время. Повторный запуск не создаёт второго победителя за тот же месяц. После закрытия поздние отправки и последующие изменения имени не переписывают архив.
- Если в месяце нет зачтённых баллов, сохраняется отметка «Нет результатов», победитель с нулём баллов не назначается.
- Общий счёт и журнал Scores не обнуляются. В новом месяце просто начинается новый отдельный подсчёт.
- Setup создаёт один таймер; повторный setup не создаёт дубликаты. Проверить его можно в редакторе Apps Script слева в разделе **«Триггеры»**: функция `closeMonthlyLeaderboard`, источник — по времени.
- Если таймер временно не запускался, чтение рейтинга автоматически закрывает пропущенные завершённые месяцы. Старт конкурса — месяц первого запуска setup Mobile 1.2; прошлые месяцы до включения функции автоматически не разыгрываются.
- Вручную для проверки можно запустить `closeMonthlyLeaderboard`. Текущий незавершённый месяц она не закрывает.

После успешной настройки в GET `/exec` должны быть `version: 3`, `ready: true`, `monthlyAutomatic: true`. Если `ready: true`, но `monthlyAutomatic: false`, база работает, а разрешение или установка таймера требуют внимания владельца. Регистрацию и рейтинг можно проверить отдельно от таймера.

## Обновление GitHub и сайта

1. Загрузите весь проект из архива в корень мобильного репозитория, включая `.github/workflows`. В корне должны находиться `index.html`, `package.json`, `mobile`, `core`, `games`, `assets`, `android`.
2. Если переменная **Settings → Secrets and variables → Actions → Variables → ARENA_API_URL** уже существует, замените её последним URL или удалите, чтобы использовался URL из `mobile/config.js`. Переменная имеет приоритет.
3. **Settings → Pages → Source: GitHub Actions**.
4. **Actions → Mobile GitHub Pages → Run workflow**. После успеха откройте опубликованный сайт и обновите страницу без кэша (Ctrl+F5 на ПК).
5. Проверьте кнопку «Проверить подключение», регистрацию с паролем из 6 символов, обязательный класс, вход, решение темы своего и другого класса и таблицу результатов.

Если браузер не загружает скрытую `.github`, создайте файлы прямо через **Add file → Create new file** с путями `.github/workflows/pages.yml` и, для APK, `.github/workflows/android.yml`, скопировав содержимое из архива. Для сайта достаточно первого файла. Дети могут играть по ссылке без APK.

## Android

- **Actions → Android APK → Run workflow** без release создаёт тестовый APK в артефакте `uchebnaya-arena-debug-apk`.
- Для подписанного APK/AAB нужен постоянный ключ. В GitHub Secrets задайте `ARENA_KEYSTORE_BASE64`, `ARENA_STORE_PASSWORD`, `ARENA_KEY_ALIAS`, `ARENA_KEY_PASSWORD`; затем запустите сценарий с release.
- Ключ подписи в архив не входит. Создайте его через Android Studio или keytool и храните отдельно. Он нужен для последующих обновлений. В репозиторий JKS и пароли не загружайте.
- Версия Android-проекта — 1.2, versionCode — 3. При следующих обновлениях увеличивайте versionCode. При необходимости до первой публикации задайте свой applicationId в `android/app/build.gradle`, namespace и пакет Java можно оставить прежними.
- Игры и текстуры включены в APK. Гостевая игра доступна без сети; вход, начало рейтинговой сессии и открытие рейтинга требуют связи.
- Используются Java 17, Gradle 8.11.1, AGP 8.10.1, API 36, WebViewAssetLoader; минимальный Android — 8.0 с современным WebView. Кнопка «Назад», отступы экрана и поворот предусмотрены. Проверяйте готовый APK на реальном устройстве.

Архив содержит подготовленные исходники. Реальная компиляция APK и публикация в магазине не выполнялись здесь; их запускает владелец в GitHub Actions. Карточка магазина, политика конфиденциальности и проверка магазина оформляются отдельно.

## Обслуживание

Лист `Scores` — источник итогового счёта, `Leaderboard` — сводка. Не удаляйте журнал, если хотите сохранить баллы и историю повторов. Блокировка аккаунта — логическое TRUE в столбце disabled листа Users. Делайте закрытые резервные копии. Google Apps Script и Таблицы имеют квоты: эта база рассчитана на учебный пилот, а не на тысячи одновременно играющих пользователей. Автоматического восстановления пароля по почте пока нет.

Публичный рейтинг показывает первые 100 аккаунтов и не возвращает логины, хеши или токены. Сеанс входа хранится в sessionStorage; после закрытия вкладки может потребоваться войти снова.

## Проверки

```sh
npm test
npm run test:mobile
npm run build:web
npm run build:android
```

`dist/` содержит только публичный сайт. В него не попадают backend, тесты, документация и ключи. `build:android` копирует тот же сайт в Android assets. Серверные тесты используют имитацию Apps Script; они проверяют все 121 сочетание классов, миграцию, сохранение баллов и секрета, права на класс, повторные запросы и одинаковые награды игр. На момент проверки последний сервер API 2 доступен и готов. Новые функции API 3 необходимо установить владельцу: заменить Code.gs и appsscript.json, выполнить setup и обновить существующее развертывание. Проверки месячного конкурса выполняются на имитации Apps Script, включая границы месяцев, архив и расписание. Реальная установка таймера в вашем Google-проекте здесь не выполнялась.
