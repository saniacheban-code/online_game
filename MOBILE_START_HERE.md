# Учебная арена Mobile 1.1

Отдельная мобильная ветка на основе итоговой GitHub 3.0: 18 предметов, 17 игр, все 34 сочетания игры и режима. Контрольная GitHub 3.0 не меняется.

## Почему появлялось «Сервис ещё не настроен»

Последний предоставленный адрес доступен, но серверный запрос рейтинга вернул `SETUP`. Это сообщение из самого Apps Script: не была завершена настройка базы. Наличие URL `/exec` означает, что опубликован код; оно не создаёт связь с Google Таблицей. Настройки одного проекта Apps Script не переносятся автоматически в другой проект.

В этой сборке уже указан ваш последний адрес:

https://script.google.com/macros/s/AKfycbyj_4-e8LKN4-kxZQtAQSrYeGP2k5mj6kYgweVDKdOSA-C37gp5s8KQC49VeUo9Q54S3g/exec

Нужны **обновление серверного Code.gs и один запуск setup владельцем**. Замены одной ссылки недостаточно.

## Обновление сервера — сделайте сначала

1. Откройте **тот же проект Apps Script, которому принадлежит последний URL**. Если уже есть аккаунты, не создавайте другой проект и не удаляйте старую таблицу.
2. Полностью замените `Code.gs` содержимым файла `backend/google-apps-script/Code.gs` из этого архива. Код также выдан отдельно файлом `Arena_Mobile_1_1_Code.gs`.
3. В редакторе выберите функцию **setup → Выполнить**. Предоставьте запрошенный доступ к Google Таблицам. **Не запускайте doPost вручную.**
4. Setup использует прежнюю базу, если её адрес уже сохранён. Иначе подключит таблицу, из которой открыт скрипт. Если проект самостоятельный и таблицы нет, setup создаст её автоматически. Ссылка на базу появится в журнале выполнения: «База настроена: …».
5. Для старой базы будут добавлены столбцы класса и коэффициентов. Существующие аккаунты, проверочные значения паролей и накопленные баллы сохраняются. Секрет `AUTH_PEPPER` не меняется. Если в непустой базе он утрачен, setup остановится и попросит восстановить прежний секрет — так пароли не будут испорчены молча.
6. Откройте **Развернуть → Управление развертываниями → карандаш → Версия: Новая версия → Развернуть**. Используйте существующее веб-развертывание, чтобы сохранить URL. Запуск — от вашего имени, доступ — «Все».
7. Откройте `/exec` в браузере. В ответе обновлённого кода должны быть `version: 2` и `ready: true`. Если `version: 1`, опубликована старая версия кода. Если `ready: false`, setup не завершён в этом проекте.

В новом окне входа есть кнопка **«Проверить подключение»**. Она различает старый серверный код и неготовую базу. Регистрацию следует проверять после готовности сервера.

Не публикуйте саму таблицу и Script Properties. В GitHub находится только публичный адрес `/exec`, а не секреты и не пароли.

## Аккаунт и класс

- Пароль — от **6 до 128 символов**. Старые более длинные пароли продолжают работать.
- На регистрации обязательно выбрать свой класс **1–11**. Без класса сервер аккаунт не создаёт.
- Старые аккаунты после входа один раз выбирают класс. Прежние баллы не пересчитываются и не удаляются.
- Класс закрепляется за аккаунтом. Для исправления или перехода в следующий класс учитель изменяет значение в столбце `grade` листа `Users` на целое число 1–11. Сам ученик не может свободно переключать класс ради награды.
- Класс виден в профиле. До запуска темы показано, сколько баллов даст её решение.

Пароли не хранятся открытым текстом: клиент использует PBKDF2-HMAC-SHA256, 600 000 итераций и индивидуальную соль; сервер хранит HMAC-проверочное значение с секретом из Script Properties. Значение длины пароля передаётся отдельно для проверки протокола; сам пароль серверу не отправляется.

## Начисление баллов

Полная награда — 10 баллов за верное полное задание. Сравнивается класс аккаунта с классом выбранных заданий; разница считается одинаково в обе стороны.

| Разница классов | Доля | Баллы |
| --- | ---: | ---: |
| Свой класс | 100% | 10 |
| 1 класс | 50% | 5 |
| 2 класса | 40% | 4 |
| 3 класса | 30% | 3 |
| 4 класса | 20% | 2 |
| 5 и более | 10% | 1 |

Пример: ученик 6 класса получает за 6 класс +10, за 5 или 7 — +5, за 4 или 8 — +4, за 1 или 11 — +1.

Эти правила одинаковы во всех 17 играх. Энергия, урон, этажи, доставка, победа и другие игровые счётчики в рейтинг не переводятся. В строительстве считается полное задание, а не каждый фрагмент. Ошибка даёт 0. В локальной дуэли аккаунт получает баллы за игрока 1; второй играет гостем. Для двух отдельных аккаунтов используйте два устройства в соло.

Награда закрепляется сервером за игровой сессией и не берётся из запроса клиента. Между зачтёнными верными ответами одного аккаунта — не менее 5 секунд во всех играх и на всех устройствах. Быстрые ответы действуют в самой игре. Повторная отправка события не начисляет баллы второй раз. Профиль и класс фиксируются в момент открытия рейтинговой сессии, чтобы отложенные результаты не меняли стоимость задним числом.

Сессия длится до 45 минут; после этого заново выберите тему. Уже открытая сессия может дослать результаты после восстановления сети в течение семи дней. Очередь — до 500 событий на аккаунт; для разных аккаунтов очереди отдельные. Гостевые результаты задним числом в аккаунт не переносятся.

Это учебный рейтинг с базовыми ограничениями, не защищённая система призовых соревнований: правильность ответа по-прежнему определяет игра на устройстве. Для строгого соревнования нужна серверная выдача задач и проверка самих ответов.

## Обновление GitHub и сайта

1. Загрузите весь проект из архива в корень мобильного репозитория, включая `.github/workflows`. В корне должны находиться `index.html`, `package.json`, `mobile`, `core`, `games`, `assets`, `android`.
2. Если переменная **Settings → Secrets and variables → Actions → Variables → ARENA_API_URL** уже существует, замените её последним URL или удалите, чтобы использовался URL из `mobile/config.js`. Переменная имеет приоритет.
3. **Settings → Pages → Source: GitHub Actions**.
4. **Actions → Mobile GitHub Pages → Run workflow**. После успеха откройте опубликованный сайт и обновите страницу без кэша (Ctrl+F5 на ПК).
5. Проверьте кнопку «Проверить подключение», регистрацию с паролем из 6 символов, обязательный класс, вход, решение темы своего и другого класса и таблицу результатов.

Если браузер не загружает скрытую `.github`, создайте файлы прямо через **Add file → Create new file** с путями `.github/workflows/pages.yml` и, для APK, `.github/workflows/android.yml`, скопировав содержимое из архива. Для сайта достаточно первого файла. Дети могут играть по ссылке без APK.

## Android

- **Actions → Android APK → Run workflow** без release создаёт тестовый APK в артефакте `uchebnaya-arena-debug-apk`.
- Для подписанного APK/AAB нужен постоянный ключ. В GitHub Secrets задайте `ARENA_KEYSTORE_BASE64`, `ARENA_STORE_PASSWORD`, `ARENA_KEY_ALIAS`, `ARENA_KEY_PASSWORD`; затем запустите сценарий с release.
- Ключ подписи в архив не входит. Создайте его через Android Studio или keytool и храните отдельно. Он нужен для последующих обновлений. В репозиторий JKS и пароли не загружайте.
- Версия Android-проекта — 1.1, versionCode — 2. При следующих обновлениях увеличивайте versionCode. При необходимости до первой публикации задайте свой applicationId в `android/app/build.gradle`, namespace и пакет Java можно оставить прежними.
- Игры и текстуры включены в APK. Гостевая игра доступна без сети; вход, начало рейтинговой сессии и открытие рейтинга требуют связи.
- Используются Java 17, Gradle 8.11.1, AGP 8.10.1, API 36, WebViewAssetLoader; минимальный Android — 8.0 с современным WebView. Кнопка «Назад», отступы экрана и поворот предусмотрены. Проверяйте готовый APK на реальном устройстве.

Архив содержит подготовленные исходники. Реальная компиляция APK и публикация в магазине не выполнялись здесь; их запускает владелец в GitHub Actions. Карточка магазина, политика конфиденциальности и проверка магазина оформляются отдельно.

## Обслуживание

Лист `Scores` — источник итогового счёта, `Leaderboard` — сводка. Не удаляйте журнал, если хотите сохранить баллы и историю повторов. Блокировка аккаунта — логическое TRUE в столбце disabled листа Users. Делайте закрытые резервные копии. Google Apps Script и Таблицы имеют квоты: эта база рассчитана на учебный пилот, а не на тысячи одновременно играющих пользователей. Автоматического восстановления пароля по почте пока нет.

Публичный рейтинг показывает первые 100 аккаунтов и не возвращает логины, хеши или токены. Сеанс входа хранится в sessionStorage; после закрытия вкладки может потребоваться войти снова.

## Проверки

```sh
npm test
npm run test:mobile
npm run build:web
npm run build:android
```

`dist/` содержит только публичный сайт. В него не попадают backend, тесты, документация и ключи. `build:android` копирует тот же сайт в Android assets. Серверные тесты используют имитацию Apps Script; они проверяют все 121 сочетание классов, миграцию, сохранение баллов и секрета, права на класс, повторные запросы и одинаковые награды игр. Реальный сервер по указанному адресу на момент подготовки ещё возвращал SETUP и требует установки нового Code.gs владельцем.
