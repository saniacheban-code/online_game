# Учебная арена Mobile 1.0

Отдельная мобильная версия на основе «Итоговая версия GitHub 3.0». Контрольная сборка 3.0 не изменена. Включены все 18 предметов, 17 игр, соло и локальная дуэль, новые цельные модели дронов.

## Что сделано

- Мобильные карточки предметов и игр, нижнее меню «Предметы / Рейтинг / Профиль».
- Соло выбрано по умолчанию. Объяснение текущего задания раскрывается снизу кнопкой «Объяснение», освобождая место для игры. Поддержаны безопасные отступы экрана.
- Формы регистрации, входа, профиля, выхода и общего накопительного рейтинга.
- Пароль преобразуется на устройстве через PBKDF2-HMAC-SHA256, 600 000 итераций и индивидуальную соль. Сервер хранит дополнительно защищённый HMAC-проверочный хеш; секрет хранится в Script Properties, а не в GitHub. Открытых паролей в таблице нет.
- Результаты привязаны к аккаунту. Повторная отправка пакета не увеличивает баллы; при потере связи результаты уже открытой рейтинговой сессии ожидают отправки.
- Готовы сервер для Google Таблиц, Android-проект и GitHub Actions для тестового APK, подписанных APK/AAB и публикации сайта.

**Архив содержит подготовленный проект, а не готовый бинарный APK.** Без настройки сервера игры работают гостем. Реальный вход и общий рейтинг включатся после развёртывания вашего Apps Script. Реальный сервис Google и компиляция Android в вашей среде ещё требуют проверки.

Адрес предоставленного веб-приложения уже внесён в `mobile/config.js`. При сборке без переменной `ARENA_API_URL` будет использован этот адрес. Переменная GitHub, если задана, имеет приоритет: удалите устаревшее значение или замените его текущим. Реальный вход и запись баллов требуют проверки владельцем после публикации.

Проверка нового сервера: HTTP 200, служба отвечает `arena-mobile`. Запрос рейтинга вернул `SETUP` («Сервис ещё не настроен»). Владелец должен один раз выполнить функцию `setup` из редактора скрипта, открытого через нужную Google Таблицу, и предоставить разрешения. Проверка регистрации и записи баллов пока не выполнена.

## 1. Подключение Google Таблиц

1. Создайте **новую пустую Google Таблицу** в своём аккаунте. Не публикуйте её и не предоставляйте ученикам доступ к самой таблице.
2. Откройте **Расширения → Apps Script**.
3. Полностью замените содержимое `Code.gs` кодом из `backend/google-apps-script/Code.gs` в этом архиве.
4. В настройках Apps Script включите отображение `appsscript.json`. Замените его содержимое файлом `backend/google-apps-script/appsscript.json`. Сохраните проект.
5. В списке функций выберите **setup** и нажмите **Выполнить**. Разрешите скрипту доступ к вашей таблице.
6. Появятся листы `Users`, `Sessions`, `Rounds`, `Scores`, `Leaderboard`. Повторный запуск setup существующие строки не удаляет.
7. Нажмите **Развернуть → Новое развертывание → Веб-приложение**. Выполнять от вашего имени; доступ — **Все**. Скопируйте адрес, заканчивающийся на `/exec`.
8. Если школьный Google Workspace запрещает такой доступ, настройку должен разрешить администратор домена. Ссылка `/dev` доступна разработчику и для учеников не подходит.

В Script Properties автоматически сохраняются `SPREADSHEET_ID` и `AUTH_PEPPER`. **Не публикуйте секрет AUTH_PEPPER и не меняйте его после регистрации учеников** — иначе старые пароли перестанут проверяться. Клиенту нужен только адрес веб-приложения `/exec`.

Лист `Leaderboard` — сводка для учителя. Источник накопленных баллов — `Scores`; не удаляйте журнал, если хотите сохранить результат и защиту от повторов. Не меняйте служебные заголовки. Делайте закрытые резервные копии таблицы. Заблокировать аккаунт можно логическим TRUE в столбце `disabled` листа Users.

## 2. Загрузка отдельного репозитория GitHub

1. Создайте новый репозиторий, например `uchebnaya-arena-mobile`, с основной веткой `main`.
2. Распакуйте архив и загрузите **всё содержимое в корень** репозитория. `index.html`, `package.json`, папки `mobile`, `android`, `backend`, `core`, `assets` должны находиться в корне, а не внутри ещё одной папки.
3. **Проверьте скрытую папку `.github/workflows`**: она обязательно должна попасть на GitHub. В ней находятся `android.yml` и `pages.yml`.
4. В репозитории: **Settings → Secrets and variables → Actions → Variables → New repository variable**. Имя — `ARENA_API_URL`, значение — ваш адрес `/exec` из Google Apps Script.
5. Альтернатива для ручной публикации: впишите адрес в поле `apiUrl` файла `mobile/config.js`. Секретов и паролей в этом файле быть не должно.

Исходная итоговая GitHub 3.0 остаётся отдельной контрольной сборкой. Не перезаписывайте её этой мобильной веткой, если хотите сохранить обе версии.

## 3. Публикация мобильного сайта

1. Откройте **Settings → Pages → Source: GitHub Actions**.
2. Затем **Actions → Mobile GitHub Pages → Run workflow**. После загрузки в main сценарий также запускается автоматически.
3. После успешного завершения откройте URL Pages из результата сценария.
4. Проверьте регистрацию двух тестовых аккаунтов. Решите задания в разных играх, откройте рейтинг, выйдите и снова войдите. Баллы должны сохраняться после входа на другом устройстве.
5. Проверьте записи в Users и Scores. В таблице нет открытого пароля: только соль, защищённый проверочный хеш и служебные данные.

GitHub Pages хранит интерфейс и игры. Вход и результаты обрабатывает Google Apps Script. Один статический HTML не заменяет сервер общей базы.

## 4. Сборка тестового APK

1. **Actions → Android APK → Run workflow**. Поле `release` оставьте выключенным.
2. Когда сценарий завершится, откройте его и раздел **Artifacts → uchebnaya-arena-debug-apk**.
3. Скачайте ZIP артефакта, распакуйте и установите `app-debug.apk` на Android-телефон.
4. Все игры и текстуры включены в APK. Гостевая игра доступна без интернета; для входа, начала рейтинговой сессии и просмотра рейтинга нужен интернет.
5. На реальном устройстве проверьте ввод, встроенную клавиатуру, поворот, звук, кнопку «Назад», открытие объяснений, вход и синхронизацию.

Используются Android API 36, Java 17, Gradle 8.11.1, Android Gradle Plugin 8.10.1 и WebViewAssetLoader. Минимальный Android — 8.0; нужен современный обновлённый WebView с Web Crypto. Оболочка не открывает произвольные локальные файлы и не предоставляет JavaScript-интерфейс к нативным методам.

Если нужно уникальное имя пакета, до первой публикации измените `applicationId` в `android/app/build.gradle`. `namespace` и пакет Java можно оставить прежними. При каждом обновлении повышайте `versionCode`.

## 5. Подписанный APK/AAB

Для релизной сборки нужен **ваш постоянный ключ подписи**. Он не входит в архив и не должен попадать в репозиторий. Создайте его через Android Studio или командой:

```sh
keytool -genkeypair -v -keystore arena-release.jks -alias arena -keyalg RSA -keysize 3072 -validity 10000
```

Сохраните JKS и пароли отдельно: они понадобятся для обновления приложения. Закодируйте JKS в Base64. В **Settings → Secrets and variables → Actions → Secrets** добавьте:

| Secret | Значение |
| --- | --- |
| ARENA_KEYSTORE_BASE64 | Полное содержимое JKS, закодированное в Base64 |
| ARENA_STORE_PASSWORD | Пароль хранилища |
| ARENA_KEY_ALIAS | Имя ключа, например arena |
| ARENA_KEY_PASSWORD | Пароль ключа |

Запустите Android APK с флажком **release**. Артефакт `uchebnaya-arena-signed-release` будет содержать APK и AAB. Для самостоятельной установки используйте подписанный APK, для магазина — AAB. Постоянный ключ должен сохраняться между обновлениями. Тестовые APK разных сборок могут иметь разные тестовые подписи.

Публикация в магазине дополнительно требует вашей карточки приложения, политики конфиденциальности и прохождения проверки магазина. Архив не означает автоматический допуск к публикации.

## Как уравнены игры

| Действие | Рейтинговые баллы |
| --- | ---: |
| Верное полное задание | +10 |
| Ошибка или тайм-аут | 0 |
| Победа, этаж, урон, энергия, доставка, собранный предмет | 0 дополнительно |
| Повторная отправка того же события | 0 повторно |
| Ответ игрока 2 в локальной дуэли | 0 в аккаунт игрока 1 |

Внутриигровые счётчики остаются прежними. Доставка может давать игровые очки, этаж строится и энергия накапливается, но в общий рейтинг переводится **решение задания**, а не величина этих разных счётчиков. В строительстве считается полное собранное задание, а не каждый фрагмент. У игры с большими числами нет повышающего коэффициента. Короткая и длинная партии одинаково оценивают каждое решение; за завершение партии бонуса нет. Множителей за предмет или класс нет.

Для всех игр и устройств одного аккаунта действует общий интервал между зачтёнными верными ответами — не менее 5 секунд. Более быстрые ответы продолжают работать в игре. Это базовый предел против накрутки, а не ограничение управления. После ошибки можно исправиться; повтор уже решённого задания без выдачи нового не начисляется.

Один аккаунт на устройстве. В локальной дуэли в рейтинг идёт игрок 1, второй играет гостем. Для накопления баллов в двух разных аккаунтах используйте два устройства в соло. Гостевые результаты задним числом в аккаунт не переносятся.

Рейтинговая сессия открывается сервером при выборе темы и действует до 45 минут; затем выберите тему заново. При временном обрыве соединения события остаются в очереди на устройстве. Допустимая задержка отправки — до семи дней, очередь — до 500 событий на аккаунт. Аккаунты имеют отдельные очереди. Сеанс входа действует до семи дней, но после закрытия вкладки может потребоваться повторный вход: токен находится в sessionStorage, пароль не сохраняется.

## Важные ограничения

- Это **учебный накопительный рейтинг**, а не защищённая система призовых соревнований. Правильность ответа определяет игра на устройстве. Технически подготовленный пользователь может подделать клиентские события. Сервер считает награду и устраняет повторы, но для строгого соревнования нужны серверная выдача задач и проверка самих ответов.
- На сайте отображаются первые 100 аккаунтов; в сводке Google — все. При равных очках место одинаковое. Публичный API не возвращает логины, хеши и токены, только игровые псевдонимы, места и баллы.
- Автоматического восстановления пароля по почте пока нет. Используйте отдельный учебный пароль, не пароль от школьной почты.
- Google Apps Script и Таблицы имеют квоты. Эта база предназначена для учебного пилота, а не для тысяч одновременно играющих пользователей. Журнал растёт; нужны резервные копии и обслуживание.
- При обновлении Code.gs создавайте новую версию **существующего** веб-развертывания, чтобы сохранить URL /exec.
- Для входа требуется HTTPS/Web Crypto. Проверяйте приложение через GitHub Pages или APK, а не двойным щелчком по file://.

## Проверки и сборка

```sh
npm test
npm run test:mobile
npm run build:web
npm run build:android
```

Для JS-сборки не нужны npm-пакеты: инструменты используют встроенные модули Node.js. `dist/` содержит только публичный сайт; backend, тесты, документация и ключи в него не копируются. `build:android` помещает тот же сайт в Android assets. Компиляция требует SDK, JDK и Gradle; сценарий GitHub устанавливает их.

Тесты аккаунтов выполняются на имитации Apps Script, игровая база проверяется автоматическими тестами. Интерфейс регистрации, повторный вход и начисление проверялись в мобильном браузере с тестовым подключением. Реальная регистрация в вашей Google Таблице и реальная компиляция APK не выполнялись без вашего развёртывания/GitHub Actions. Перед выдачей ученикам выполните пробный прогон.
