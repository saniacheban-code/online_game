# Подключение предметов и игр

## Разделение ответственности

Страница выбирает предмет и тему. Предмет создаёт поток заданий. Игра получает этот поток через `configureArena`, рисует сцену и сообщает о верных и неверных ответах. Генератор не находится в файлах игр.

Внутри `games/<код>/engine.js` общая отрисовка, звук и анимации хранятся один раз. Различия сохранённых режимов явно отмечены ветками `isSolo`. Разметка каждого режима вынесена отдельно, чтобы сохранить расположение его элементов. При правке общей функции изменение действует в обоих режимах; при правке ветки режима нужны соответствующие проверки.

## Формат задания

Предмет возвращает объект со следующими полями:

| Поле | Содержимое |
| --- | --- |
| `id` | Идентификатор задания |
| `subjectId` | Код предмета |
| `prompt` | Условие; разрешена разметка доверенного учебного банка |
| `choices` | Массив строк с вариантами ответа, для текущих игр — четыре |
| `correctIndex` | Индекс верного ответа |
| `seconds` | Время ответа |
| `level` | Сложность 1–3 |
| `metadata` | Класс, тема и дополнительные сведения |

`Arena.taskSession` проверяет задание и добавляет адаптер совместимости `q/o/ci/t`, который используют сохранённые игры. Математические поля пояснений остаются внутри математического предмета.

Это формат данных задания. Способ ответа ученика определяет игра: в автогонках утверждение «верно/неверно» строится из этого объекта; в лесу выбираются три ответа; башни в режиме на двоих проверяют введённое значение.

## Сессия

Результат `subject.createSession(options)` — вызываемая функция:

```js
const next = subject.createSession({
  grade: 6,
  topicIndex: 0,
  mode: 'solo',        // 'solo' или 'two'
  difficulty: 0,       // 0, 1 или 2
  game: 'towers'
});

const question = next(0); // свой вопрос для каждого участника
next.answer(0, true);
next.reset();
```

Для забега `next(player, lane)` получает номер полосы 0–2. Уровень и баллы соответствуют полосе.

Одиночная сессия предоставляет `next.solo`: компьютер использует `tick`, `record`, `reset`, `time`; помощник — `lesson` и `render`. Общий `Arena.createOpponent` в `core/teaching.js` создаёт этот контроллер и принимает функцию объяснения предмета. Пояснение должно храниться вместе с конкретным заданием. Создавайте его при генерации вопроса; не выбирайте независимый пример только по названию темы.

## Новый предмет

1. Добавьте `content/<код>/generator.js`.
2. Зарегистрируйте предмет через `Arena.registerSubject`.
3. Укажите темы по классам: `{ id, title, section, quarter, index }`.
4. Реализуйте `createSession` с общим форматом заданий и обоими режимами.
5. Подключите файл предмета после `core/registry.js` и `core/teaching.js` на странице предмета.
6. Используйте общий каталог `core/games.js` и существующие страницы игр.
7. Проверьте содержание, ответы, сложность и объяснения. Автоматическая регистрация не проверяет соответствие вопросов ТУП.

Подключены математика, физика, химия, биология, география и информатика. Главная страница `index.html` показывает метаданные из `core/subjects.js`; она не загружает генератор. Математика открывается в `subjects/math.html`, физика — в `subjects/physics.html`, химия — в `subjects/chemistry.html`, биология — в `subjects/biology.html`, география — в `subjects/geography.html`, информатика — в `subjects/informatics.html`. Страница каждого предмета загружает свой независимый генератор. Остальные страницы сообщают о подготовке заданий.

Чтобы подключить подготовленный предмет, замените его страницу рабочим меню с подключением собственного генератора, укажите `data-subject="<код>"` у `body` и включите `available` в общем списке. `core/app.js` берёт код предмета из страницы или явного параметра адреса. Неизвестный код показывает сообщение, а не подставляет математику.

Страницы предметов используют `<base href="../">`, поэтому пути к общим ресурсам записываются относительно корня проекта. Возврат к предметам — ссылка `index.html`; игры возвращают ученика к выбранным темам через `onExit`.

Регистрация другого предмета проверяется в `tests/catalog.cjs` на небольшом вымышленном банке. Этот банк существует только в тесте и не показывается ученикам.

## Новая игра сразу для предметов

1. Создайте папку `games/<код>/` с `engine.js`, `two.html`, `solo.html`.
2. В каждой странице подключите `../../core/runtime.js` перед `engine.js`. Укажите `<body data-play-mode="two">` или `solo`.
3. Объявите в движке:

```js
window.configureArena = (next, label, onExit, context) => {
  // next(player, lane) выдаёт вопрос выбранного предмета.
  // next.answer(player, ok) сообщает результат генератору.
  // next.reset() начинает новую попытку.
  // onExit() возвращает к темам и выгружает игру.
};
```

4. Используйте `context.grade`, `context.topicIndex`, `context.topics` только для подписей. Не обращайтесь к математическому банку напрямую.
5. Добавьте одну запись в `core/games.js` и выполните `npm run build`, чтобы подготовить оболочки. Все страницы предметов, использующие общий каталог, увидят новую игру.
6. Если игра требует нового типа заданий, сначала расширьте договор между предметом и игрой и проверки совместимости. Текущая основа рассчитана на четыре варианта в данных задания; развёрнутые сочинения и ответы без автоматической проверки потребуют другого интерфейса.
7. Добавьте проверки обоих режимов в `tests/`.

## Общие ресурсы

Каждое изображение расположено в `assets/images/` и используется по относительному пути. Оформление и экранные настройки вынесены в `assets/css/` и `assets/js/`. Относительные ссылки сохраняют работу при размещении проекта в подпапке.

Не вставляйте обратно большие base64-изображения или код другой игры в движок. Меняйте общий ресурс или файл нужного движка. `core/game-pages.js` — автоматически формируемая копия небольших HTML-оболочек для `srcdoc`; в ней нет логики игр или копий изображений. Редактируйте исходные `games/<код>/<режим>.html` и выполняйте `npm run build`.

## Локальный запуск без междокументной блокировки

Меню читает HTML-оболочку из `Arena.gamePages`, вставляет абсолютный `<base>` по адресу исходного файла и задаёт `iframe.srcdoc`. Окно наследует происхождение меню. Ссылки внутри оболочки ведут к исходным файлам игры, стилей и картинок. Чтение `configureArena` у отдельного `file:`-документа больше не используется.

Проверки `tests/local-launch.cjs` имитируют запрет прямого доступа к отдельному окну до создания `srcdoc`, проверяют 8 игр × 2 режима, Windows/Linux/file URL и адрес сайта в подпапке. Сборщик оболочек работает без внешних зависимостей.

Смена предмета доступна ссылкой `_top` из панели каждой игры. Общие стили навигации: `assets/css/arena-navigation.css`. Размеры черновика леса: `assets/css/forest-workspace.css`; файл подключается последним в обеих страницах леса. После изменения игровых HTML выполните `npm run build`.

В информатике шаблоны формируют также аудиторские записи программ и запросов. `tests/informatics.cjs` передаёт только собственные сгенерированные примеры в `tests/check-informatics.py`: файлы виртуальные, SQL-база в памяти. Эта зависимость нужна только разработчику; клиентский сайт остаётся статическим.


## Строительство небоскрёба и новое меню

`builder` — общий движок на двоих. Он преобразует текущее предметное задание в заполняемый блок через `games/builder/puzzles.js`, а `model.js` отдельно ведёт 150 секунд, этажи, шесть ошибок и итог. Установки фрагментов разделены по игрокам, указатели хранятся независимо. Полная сборка вызывает `next.answer` один раз. Игра использует тот же договор подключения и оболочку `srcdoc`, что сохраняет запуск с диска. В сборнике десять игр и 18 поддерживаемых сочетаний игры/режима.

Новые иллюстрации меню — `assets/images/game-covers-v2.png`. `Arena.catalogIcons` задаёт измеренные координаты отдельных кадров; `core/app.js` подставляет их в карточки, общие для всех предметов. Старые изображения оставлены, поскольку используются внутри существующих игр.
